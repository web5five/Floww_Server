# F012 AI merchant proposal / AI 판매자 제안

Executable synthetic input/output cases and Ria mapping worksheet / 실행 가능한 합성 입출력 예시와 Ria 매핑 표: [F013 integration examples](AI_INTEGRATION_EXAMPLES_KO_EN.md).

Status / 상태: **candidate internal component**, local code and loopback fixture verification only. This document does not approve a shared HTTP API, signer policy, merchant integration or payment. / **내부 후보 컴포넌트**이며 로컬 코드와 루프백 픽스처만 검증했습니다. 공용 HTTP API, 서명 정책, 판매자 연동, 결제를 승인하지 않습니다.

## Caller contract / 호출자 계약

`new AiMerchantProposal(kilnClient, clock).propose(context, quotes)` is an ordinary Java call. No controller, Spring registration, store, merchant gateway, wallet or signer is added. `Context` carries caller task and mandate references/revision, item ID, positive integer maximum total **base units**, exact `Asset(chainId, tokenAddress, decimals)`, absolute mandate deadline, merchant/recipient allowlist, required fulfillment deadline, verified synthetic prescription/identity eligibility (`true`, `false`, or unknown), and mandate activity snapshot. These must come from a trusted core caller, not a request boolean. `ACTIVE` only permits proposal evaluation. It is not proof of on-chain delegation, fresh user confirmation or payment authority. / 신뢰 가능한 코어 호출자가 제공한 스냅샷만 받습니다. `ACTIVE`는 제안 평가용 상태이며 온체인 위임, 최신 사용자 확인, 지급 권한의 증거가 아닙니다.

Each `Quote` is a caller-supplied immutable snapshot: unique quote ID, merchant, recipient, item, exact asset, **total including delivery** in integer base units, expiry, stock, promised fulfillment time and prescription/identity requirements. The component never fetches a merchant or computes currency conversion. Separate native-network gas or other user-paid fees need an explicit core/signer accounting policy before any payment; this component does not establish an all-in user cost. / 견적 총액에는 배송비를 포함합니다. 별도 네트워크 가스비 등 사용자 부담 비용은 코어·서명 담당자의 정책이 필요하며, 이 컴포넌트가 최종 전체 비용을 증명하지 않습니다.

One call accepts at most 16 quotes and 16 permitted pairs; text fields are bounded to 128 Java characters, and positive integer amount strings to 38 digits. It rejects duplicate quote IDs, duplicate/conflicting merchant mappings, contradictory allowlist pairs, malformed amounts and invalid bounds. Missing required mandate boundaries return `CLARIFICATION_REQUIRED` before a provider call. Eligibility unknown only blocks quotes that require that evidence; if those are the only quotes, the result requests clarification. / 견적과 허용 쌍은 각각 최대 16개이며 식별자·금액 길이를 제한합니다. 필요한 적격성 증거가 미확인인 견적만 차단합니다.

## Evaluation and output / 평가와 출력

The component annotates each quote with stable reason codes. Examples: `ITEM_MISMATCH`, `ASSET_MISMATCH`, `RECIPIENT_NOT_PERMITTED`, `OVER_BUDGET`, `QUOTE_EXPIRED`, `OUT_OF_STOCK`, `FULFILLMENT_TOO_LATE`, `IDENTITY_EVIDENCE_MISSING` and `IDENTITY_NOT_VERIFIED`. No eligible quote yields `NO_CANDIDATE`, with no model call. It sends only eligible bounded snapshots as JSON user data to the existing KilnClient and permits the existing `propose_purchase` tool, whose only argument is `quoteId`. Merchant text cannot set system instructions. / 적격 견적만 데이터로 모델에 전달하며 판매자 문자열을 지시로 취급하지 않습니다.

The result is `PROPOSED`, `CLARIFICATION_REQUIRED`, `NO_CANDIDATE`, `REJECTED`, or `MODEL_FAILURE`; it has a reason, task/mandate/revision references, per-quote findings, and optional provider provenance (actual model ID, endpoint-derived evidence mode, finish reason, tool/generation IDs, usage status and values, provider cost string, attempt count). Only `PROPOSED` contains the original immutable selected quote. Strict duplicate-key JSON parsing, exact `quoteId`-only arguments, model/tool/finish verification and eligible membership reject forged or changed model selections. Expiry and fulfillment timing are rechecked after inference. The proposal is sent to separate deterministic controls; it is never executable authority or payment/fulfillment success. / `PROPOSED`에도 결제 권한이나 이행 성공 의미가 없으며, 결정적 통제 계층에서 별도로 검증해야 합니다.

Example with synthetic MockUSDC (fixture decimals 6 only): maximum `60000000`; A `43000000` eligible, B `47000000` requires unverified identity, C `63000000` over budget. Supplying verified identity makes B eligible. These are **synthetic test values** and no real medicine, prescription, merchant, token address or legal eligibility is asserted. / 예시는 합성 시험 데이터이며 실제 의료·법적 적격성을 주장하지 않습니다.

## Freshness and owner handoff / 최신성 및 담당자 인계

The component holds immutable caller snapshots during the call. It cannot observe a merchant changing a quote or an on-chain mandate/receipt changing afterward. The core and signer owners must fetch and compare fresh authoritative quote, task, receipt, delegation and balance state at their actual enforcement boundary; apply the earlier of quote and mandate deadlines; account for all user-paid fees; and enforce idempotency before execution. Actual signer, token and chain selection, merchant integration, order acceptance, payment and fulfillment remain unresolved owner work. A retry of this Java proposal may repeat a billable Kiln request; provider-internal retry is distinct from caller retry. / 실행 담당자는 최신 견적·위임·확인 기록과 전체 비용을 권한 경계에서 다시 검증해야 합니다. 이 컴포넌트를 재호출하면 새로운 유료 모델 호출이 생길 수 있습니다.

Verification / 검증: offline Java 21 Maven tests use a loopback provider only. They prove local validation and protocol behavior, not real model ranking quality, merchant eligibility, prescription verification, on-chain enforcement or user acceptance. / 테스트는 로컬 유효성 검증과 프로토콜 동작만 증명합니다.
